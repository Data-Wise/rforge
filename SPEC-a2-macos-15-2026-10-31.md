# SPEC: Move the A2 release gate from macos-14 to macos-15

**Status:** draft, 2026-10-31 · **Issue:** #115 · **Amends:** `SPEC-docs-check-a2-2026-10-12.md` (platform set only)

## Problem

GitHub retires the `macos-14` runner image on 2026-11-02 (actions/runner-images#13518); scheduled
brownouts already cancel the job at 0 s. The A2 gate hard-requires `{ubuntu-24.04, macos-14}`, so no
A2 acceptance can be produced after retirement, and release PRs to `main` get a red
`a2-release / macos-14` job (not merge-blocking: `main` has no required status checks).
Existing v2.22.0 and v2.22.1 evidence stays valid.

## Decisions (grilled 2026-10-31)

| # | Decision | Reason | Rejected |
|---|---|---|---|
| 1 | Replace with `macos-15` | Probe run 41230922650 passed 679/680 on it (R 4.6.1 and locked packages provisioned); pinned label keeps the gate reproducible | `macos-26` (untested, Arm64-only listing), `macos-latest` (floats under an exact-lock gate) |
| 2 | Keep two required platforms: `ubuntu-24.04` + `macos-15` | Dropping macOS silently lowers the accepted contract and would itself need review | Ubuntu-only; macOS advisory (needs new verifier code) |
| 3 | Short SPEC + adversarial review of the diff | The edits touch gate code (verifiers, manifest) | Issue comment only; no review |

## Change set

1. `.github/workflows/a2-platform.yml:14` matrix `[ubuntu-24.04, macos-15]`.
2. `scripts/verify_a2_aggregate.py:20` platform loop.
3. `scripts/verify_a2_release.py:279` exact platform set.
4. `tests/a2/required.json` and `tests/a2/fixture-lock.json` platform entries.
5. `tests/a2/test_release_ci.py` guard test and any manifest node IDs it changes.
6. `docs/guides/docs-audit.md` platform wording.

No other behavior changes. Grep the repo for `macos-14` afterward; only archived specs may keep it.

## Invariants (must not change)

- `validate_review` stays strict; re-attest with an honest delta note, never loosen it.
- The platform set stays exact (two platforms, no wildcard, no `macos-latest`).
- Evidence stays bound to the candidate SHA; `pytest==8.4.2` pin stays in the A2 workflows.
- Default `/rforge:docs:check` stays offline; no command-surface change.

## Verification

1. Local gate in the worktree: `bash tests/test-all.sh` (47 checks) and
   `PYTHONPATH="$PWD" python3 -m pytest tests/a2 tests/harness tests/test_*.py -q` in a Python >= 3.10
   venv with `pytest==8.4.2`; report counts.
2. Adversarial review of the diff (review-fix-loop), findings triaged against source.
3. Re-attestation on the final SHA: `a2-observations` with a review record whose `reviewed_commit`
   equals that SHA and an honest `delta_note`, then `a2-release` with the new run ID. Pass means both
   platform jobs green and the aggregate verifier accepts both artifacts.
4. Collected node count stays 680, or the manifest records the exact change.

## Risks and open questions

- **Release timing:** the change reaches `main` only through a `dev -> main` release. Until then a
  release PR shows a red macos-14 job (expected, not blocking).
- **Architecture:** `macos-15` arm64 vs Intel is not stated in the runner-images issue; confirm from
  run output (`uname -m` or runner info) and record it here before acceptance.
- **Platform drift:** newer macOS may change pkgdown/knitr output; the probe saw none in 679 tests.
- **Short runway:** `macos-15` will itself be retired; note the next migration in `.STATUS`.
- **Pending #110:** `download-artifact@v8` can only be verified once both platform jobs run.

## Out of scope

Dependabot config, #110 itself, and any relaxation of A2 acceptance rules.
